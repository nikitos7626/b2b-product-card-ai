# B2B Product Card AI Assistant · AI-помощник подготовки карточек товаров КИПиА

Прототип промышленного сервиса для автоматической генерации и валидации черновиков карточек товаров контрольно-измерительных приборов и автоматики (КИПиА) для B2B интернет-магазина.

Сервис принимает технические данные о приборе (наименование, производитель, словарь характеристик, фрагмент паспорта) в формате JSON или через веб-форму и формирует готовый черновик карточки с гарантией отсутствия выдуманных характеристик.

---

## 🚀 Быстрый запуск

### Шаг 1. Клонирование и настройка окружения
```bash
git clone https://github.com/nikitos7626/b2b-product-card-ai.git
cd b2b-product-card-ai
cp .env.example .env
```
В файле `.env` укажите ваш API-ключ Gemini:
```ini
GEMINI_API_KEY=ваш_ключ_google_ai_studio
```
*(Модель `gemini-flash-lite-latest` уже зашита в дефолтные настройки приложения, указывать `GEMINI_MODEL` не требуется).*

---

### Шаг 2. Запуск сервиса (выберите удобный способ)

#### Способ 1: Запуск через Docker (Рекомендуемый)
```bash
docker compose up --build
```
Сервис автоматически соберет контейнер и поднимется на `http://localhost:8000`.

#### Способ 2: Локальный запуск на Python
```bash
pip install -r requirements.txt
python -m app.main
```
- **Интерактивный веб-интерфейс:** `http://localhost:8000`
- **Интерактивная документация Swagger OpenAPI:** `http://localhost:8000/docs`
- **Проверка здоровья (Health-check):** `http://localhost:8000/api/health`

## 📋 Что формирует сервис (Требуемый результат)

Для каждого товара сервис генерирует:
1. **SEO-заголовок (тег Title):** строго **до 70 символов** с ключевыми параметрами прибора.
2. **SEO-описание:** связный технический текст объемом **800–1 200 символов** в строгом B2B-стиле (без рекламной «воды» и клише).
3. **Структурированный список характеристик:** таблица параметров. Все значения берутся **строго из входных данных** (при отсутствии параметра — пометка *«данных нет»*).
4. **Нормализация параметров по ГОСТ:** единицы давления (`0–1,6 МПа`), токовые сигналы (`4...20 мА`), резьбы (`G1/2`, `M20×1,5`), температура (`-50...+180 °C`).
5. **3–5 поисковых запросов:** семантическое ядро страницы (брендовые, параметрические, коммерческие и инженерные запросы).
6. **Commercial-блок для менеджера по продажам:** целевая аудитория (ЖКХ, энергетика, нефтегаз, пищепром) и решаемые прибором инженерные задачи.
7. **Отчет о полноте данных (Data Quality Report):** выявление отсутствующих критических характеристик и полей, требующих уточнения (чисел без единиц измерения).
8. **Семантическая микроразметка Schema.org `Product` (JSON-LD):** готовая структура для поисковой оптимизации (Rich Snippets).
9. **Форматы вывода:** мгновенное копирование в буфер обмена в форматах **Markdown** и **JSON**.

## 🛠️ Архитектура и структура проекта

Проект построен по принципам слоистой чистой архитектуры (Clean Architecture / MVC) с разделением ответственности и безопасной моделью многопоточности:

```text
b2b-product-card-ai/
│
├── app/
│   ├── controllers/            # Модульные контроллеры (FastAPI APIRouter)
│   │   ├── card_controller.py   # Бизнес-эндпоинты (/api/generate, /api/examples/{id})
│   │   ├── system_controller.py # Системные эндпоинты (/api/health, /favicon.ico, UI)
│   │   └── __init__.py          # Экспорт роутеров
│   │
│   ├── config.py               # Валидация конфигурации через Pydantic Settings
│   ├── schemas.py              # Pydantic v2 контракты (ProductInput, DraftCardResponse, Schema.org)
│   ├── prompt.py               # Лаконичный системный промпт (E-E-A-T, SEO-интенты, без дубликатов)
│   ├── llm_client.py           # Универсальный REST-клиент (Gemini + OpenAI) с 3-ступенчатым exponential backoff
│   ├── validator.py            # Детерминированный нормализатор ГОСТ, Grounding Verifier и таксономия КИПиА
│   ├── service.py              # Оркестратор пайплайна, генератор Markdown и Schema.org JSON-LD
│   └── main.py                 # Тонкая фабрика приложения create_app() без бизнес-мусора
│
├── static/
│   └── index.html              # Минималистичный SPA-интерфейс (темная тема, сетка 1.8fr, живые счетчики)
│
├── data/
│   ├── categories_taxonomy.json # Спарсенная таксономия 238 категорий КИПиА (souz-pribor.ru)
│   ├── product_1.json          # Тестовый товар №1: Манометр показывающий DM 02 («Манотомь»)
│   └── product_2.json          # Тестовый товар №2: Датчик давления ОВЕН ПД100-ДИ
│
├── output/                     # Эталонные сгенерированные результаты и батч-отчеты
│   ├── product_1_result.json / product_1_result.md
│   ├── product_2_result.json / product_2_result.md
│   └── batch_20_categories_report.md / batch_20_categories_report.json
│
├── tests/
│   └── test_service.py         # 11 изолированных юнит-тестов (время прогона ~0.35 с)
│
├── test_20_categories.py       # Сквозной интеграционный бенчмарк по 20 категориям
├── Dockerfile                  # Оптимизированный контейнер для развертывания
├── docker-compose.yml          # Декларативный запуск сервиса одной командой
├── .env.example                # Шаблон переменных окружения
└── requirements.txt            # Зависимости (FastAPI, Pydantic, HTTPX, Pytest)
```

### Архитектурные особенности:
1. **Неблокирующий Concurrency:** Роуты контроллера объявлены как синхронные `def`, благодаря чему FastAPI автоматически исполняет синхронные вызовы внешних API и регулярных выражений в пуле потоков Starlette (`threadpool`), гарантируя, что асинхронный цикл событий (Event Loop) никогда не блокируется.
2. **Отсутствие мертвого кода:** В монолитном SPA убран избыточный `CORSMiddleware`, а оффлайн-заглушки вынесены из продакшен-кода в тестовые фикстуры `pytest`.

## 🛡️ Принятые решения и защита от галлюцинаций (Zero Hallucination)

В контрольно-измерительных приборах неверная цифра диапазона или резьбы штуцера ведёт к авариям или срывам закупок. В проекте реализован **многоуровневый барьер проверки**:

1. **Детерминированный нормализатор единиц (`app/validator.py`):**
   - Программный код приводит написание технических параметров к стандартам отрасли (ГОСТ/ТУ) со 100% точностью, не перекладывая эту рутину на вероятностную модель.
2. **Детерминированный Python Grounding Verifier (`app/validator.py`):**
   - Независимый программный код разбирает выходную таблицу характеристик и проверяет числовые параметры по исходному тексту запроса.
   - Если модель добавила выдуманное число, параметр маркируется предупреждением `[⚠️ требует проверки источника]`.
3. **Таксономический валидатор полноты данных:**
   - Сервис использует базу из **238 категорий приборов КИПиА**, спарсенных с реального промышленного каталога `souz-pribor.ru`.
   - Для каждой категории зафиксирован эталонный список обязательных атрибутов (`required_specs`).
   - Если прибор относится к категории «Манометры показывающие», а в запросе не передана присоединительная резьба или класс точности, система явно уведомляет контент-менеджера в блоке замечаний.
4. **Детектор сомнительных значений:**
   - Автоматически находит параметры без единиц измерения (например, `"давление": "16"` — неясно: Па, кПа, бар или МПа) и расплывчатые термины (`"обычная"`).

## ⚠️ Ограничения решения и вектор дальнейших улучшений

### Текущие ограничения MVP:
1. **Отсутствие постоянного хранилища (БД):** по условиям ТЗ сервис работает на лету и не сохраняет историю запросов в СУБД.
2. **Синхронный конвейер:** генерация выполняется в рамках одного HTTP-запроса (при больших очередях селлеров эффективнее асинхронный Task Queue через Celery/Redis).
3. **Локальный веб-интерфейс:** выполнен в виде легковесного SPA без авторизации пользователей и ролевой модели.

### Возможности для масштабирования в Production (Roadmap):
1. **Гибридный пайплайн со спановым экстрактором GLiNER:**
   - Для высоконагруженного продакшена (миллионы товаров) экономически эффективно использовать двухуровневую обработку:
   - Локальный экстрактор **GLiNER** (20–40 мс на прибор) извлекает сущности со 100% гарантией отсутствия галлюцинаций и сжатием факт-листа;
   - **LLM** привлекается только для генерации продающего SEO-текста и коммерческих выводов. Это снижает расходы на токены на 60–70%.
2. **Пакетная загрузка прайс-листов:** обработка файлов Excel/CSV на 10 000+ позиций в фоновом режиме.
3. **Экспорт в CMS:** прямая интеграция через API с 1C-Битрикс, OpenCart или ERP-системой предприятия.
4. **OCR паспортов приборов:** распознавание сканов заводских паспортов и свидетельств об утверждении типа средств измерений (PDF/TIFF) с автоматическим парсингом таблиц погрешностей.
